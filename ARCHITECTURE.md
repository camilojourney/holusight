# Holusight architecture - source scanner

Holusight helps agents find source duplication and explicit fact drift. It is not a search/index/LLM application. `src/holusight/alignment.py` detects source duplication candidates and shared-fact contradictions. `paths.py` holds repository path confinement and Markdown line filtering. `focus.py` supplies shared validated file/directory/Markdown finding selectors. `api.py` exposes `Holusight.align`; `__main__.py` plus `cli_axi.py` expose the same operation as `python -m holusight align` and `holus align`.

## Data and trust boundary

The scanner reads repository source files only and never writes checked repositories. No subprocess other than Git file enumeration, model, embedding daemon, network client, index, or SQLite cache is invoked. Paths must resolve inside the repository; symlinks escaping the root are refused.

## Public contract

- `holus align [repo] [--scope <file-or-directory>] [--docs] [--against <repo-relative-report>]` and `Holusight(repo).align(scope=None, against=None, docs=False)` rescan current source and compare explicit declarations/duplicate candidates. Reports use schema `holus-alignment-report/v2`.

`--docs` selects supported `.md` files within the existing safe inventory, including specs/root instructions, not just `docs/`. It intersects any scope. Normalized directory scopes include descendants by path components, not loose prefixes; scope symlinks/escapes are refused. Source alignment emits findings with a selected anchor (retained even with bounded partner locations) and still scans outside comparison partners. Empty/unrepresented focus is partial. Baselines bind `docs` and normalized scope/kind; file-to-directory changes are incompatible. v3 receipts require matching analyzer rules and explicit selector metadata; legacy v1/v2 receipts are incompatible and must be regenerated. Output reduction is navigation evidence, not proof of scanner savings or agent productivity.

## Deterministic source checks and refresh

The scanner inventories Git tracked/unignored recognized source extensions (or walks a non-Git directory), excluding derived/dependency and private runtime directories. `_SOURCE_EXTENSIONS` in `alignment.py` owns the finite metadata-only recognition list; it is not exhaustive language detection. Only `.py`/`.md` contents are analyzed. `coverage.extensions`, `inventory_files`, `supported_files`, `unsupported_files` and `focused_unsupported_files` distinguish inventory from successfully read `files`/`focused_files`. Selected unsupported sources produce skipped evidence and incomplete `partial` reports without consuming supported-source byte/file budgets. An empty inventory is `unavailable` and incomplete. Supported-only scopes/Markdown focus retain global unsupported counts without claiming whole-repository coverage. Source symlinks are refused. None of these selectors is a privacy boundary: supported outside partners can still be read. Use a separately allowlisted code-only snapshot for private mixed repositories. Python functions with at least three statements and 20 AST nodes are fingerprinted without docstrings/function name; optional local-renaming candidates preserve literals, operators, external identifiers, defaults, decorators and annotations. Normalized locals use impossible parsed-identifier sentinels in AST dumps so external names such as `local_0` cannot collide with local slots. Nested binding constructs remain conservatively excluded from renamed matching. These are structural candidates, not proven behavioral equivalence; identical global names can refer to different module state. Markdown paragraphs need 30 words; exact whitespace-normalized duplicates and >=0.85 five-word-shingle Jaccard matches are advisory. A shingle index avoids comparing unrelated paragraphs.

Explicit `holus:fact` markers link JSON scalar declarations in Markdown to unambiguous top-level Python scalar literal declarations by a shared key. Disagreeing values produce code/code, docs/docs or docs/code mismatch evidence. Dynamic declarations, malformed markers and syntactically ambiguous bindings prevent a complete verdict. Python comment markers accept optional whitespace after `#`; malformed `#holus:fact` and `# holus:fact` prefixes are equally unverified, not silently dropped. Assignment-expression/header rebinding, deletion, exception/pattern bindings, wildcard imports and global mutation invalidate affected declarations conservatively. This is syntactic rejection, not data-flow interpretation. Code markers must be module-level, at column zero or inline with a top-level declaration; function/class markers and indented standalone markers are unverified. Imports/eval/doctests/project functions are never executed; markers inside Python strings or supported Markdown code examples are not contracts. Both scanners share fenced/indented-line filtering: matching delimiter character, closing run at least the opening length, up to three leading spaces and only ASCII space/tab after a closing run. Lists/quotes and full Markdown rendering are not interpreted. This does not validate arbitrary prose or runtime behavior.

Every run re-reads source; SHA-256 manifests, rule/Python version and scope bind the report. Rechecking bytes/inventory at completion detects concurrent edits. No cache invalidation or watch service is needed. Corrected source rules identify themselves as `holus-alignment/v3`; v1/v2 baselines are incompatible even if their hashes/IDs happen to match. Every v3 baseline must explicitly bind `docs` and the normalized selector. Matching complete saved reports produce new/persisting/resolved IDs and changed/deleted source paths, without interpreting resolution as functional correctness. Limits: 500 files, 256 KB/file, 10 MB total bytes, 2000 units, 1000 facts and 5000 candidate paragraph comparisons. Truncation and unverified coverage are explicit; incomplete scans cannot establish resolved findings. Receipt/source files are never written by the tool.

`--scope` accepts only paths contained inside the repository. The old index/search/ask/serve/demo, semantic evidence, web UI, embedding daemon, autonomous evaluation, and Graphify graph-check (`check`/`status`) surfaces are retired; see [ADR 0020](docs/decisions/0020-retire-graphify-graph-checks.md). Historical specs/ADRs remain as provenance; `specs/029-deterministic-duplication-alignment.md` is the operational contract.
